# Corbett Report Migration Runbook

This runbook describes one migration batch from start to finish.

## Batch model

Each batch contains two groups:

- Newer WordPress posts that were not in the previous QDN catalog.
- The next group of older historical posts.

The default starts with 50 historical posts. For the first batch, use 10. Increase the size only after a batch works from beginning to end.

Progress is stored in:

```text
workspaces/corbettreport-batches/state.json
```

Do not edit this file by hand unless a maintainer asks you to.

## Before every batch

Start Qortal Hub, log in with the `Corbett` account, and wait for synchronization. Then run:

```bash
npm run doctor
npm run batch:status
```

If no batch has ever been prepared, run this once:

```bash
npm run batch:init -- --from-qdn
```

## Prepare the next batch

Use a small first batch:

```bash
CORBETT_BATCH_SIZE=10 CORBETT_RECENT_LIMIT=10 npm run batch:next
```

For later batches:

```bash
npm run batch:next
```

The default historical batch size is 50 posts. The default recent limit is 100 posts.

If a download fails:

```bash
npm run batch:retry
```

The retry skips completed files and retries missing media. The terminal prints the batch folder to use in the Migration Publisher.

## Publish the batch

Open:

```text
qortal://WEBSITE/Corbett
```

Use the `Corbett` account. Select the exact batch folder printed by the terminal.

Recommended order:

1. `CMS JSON` - posts, pages, indexes, the cumulative manifest, and a sample image.
2. `Full media` - all downloaded media in the current batch.

For a slow connection, replace `Full media` with:

1. `Images`
2. `Documents`
3. `Audio`
4. `Video`
5. `Selected media` for any remaining files

Keep `Skip already published` enabled. Re-publishing is safe because the publisher checks QDN first, but it still takes time.

### What gets updated

The batch contains a cumulative import catalog. Publishing the indexes updates:

```text
cr-qdn-manifest
cr-posts-index
cr-pages-index
cr-categories
cr-tags
cr-media-map
cr-url-map
cr-import-manifest
```

The cumulative catalog includes older posts recorded from QDN during `batch:init -- --from-qdn`. This prevents a new batch from hiding the older archive.

## Adopt the posts in the CMS

Open:

```text
qortal://WEBSITE/CorbettReport
```

Go to `Author Backend` -> `Imported`.

Use:

```text
Import source: Corbett
Manifest: cr-qdn-manifest
```

Then:

1. Click `Load Imported Content`.
2. Filter to `Not adopted`.
3. Select the new posts.
4. Click `Adopt selected`.
5. Open `Posts`.
6. Filter to `Draft`.
7. Select the adopted posts.
8. Publish them.

The CMS keeps the historical WordPress publish date. The public site should place the posts in editorial date order, not the QDN publication time.

## Verify the public site

Open `qortal://WEBSITE/CorbettReport` and check:

- Newest posts appear at the top.
- Historical posts appear in the correct older position.
- Post text is readable.
- Featured images and inline images load.
- Video and audio links open.
- The page does not show a cached empty catalog.

If the site still shows old data, refresh or reopen the app. Large QDN resources may take time to download through Qortal Hub.

## Complete the batch

Only after publishing, CMS adoption, CMS publishing, and the public check:

```bash
npm run batch:complete
```

This advances the historical and recent-post cursors.

## Clean up local files

After the batch is verified:

```bash
npm run batch:cleanup
```

This deletes the large raw, converted, and media files from that completed batch. It keeps small audit files in:

```text
workspaces/corbettreport-batches/receipts/
```

It does not delete QDN resources.

Keep an external backup if you may need to republish the same media later.

## Recovering from problems

### `A prepared batch is already waiting`

Finish the publish and CMS steps, then run `npm run batch:complete`.

### `Batch N is failed`

Run:

```bash
npm run batch:retry
```

If retry fails, read the terminal error and the files in the batch `logs/` folder.

### Missing media

The toolkit preserves missing or blocked media as external links. The batch is still usable. Check the public post and retry later if the file becomes available.

Set this only when you need a strict check that must fail on any missing download:

```bash
CORBETT_ALLOW_MISSING_MEDIA=false npm run batch:retry
```

### Do not skip `batch:complete`

Skipping it causes the next batch to reload the same posts. Complete it only after verifying the public site.
